# quickstart-chat — Haskell browser client (wasm)

A browser chat client whose SpacetimeDB protocol handling, BSATN decoding, state
management, and view rendering are all **Haskell compiled to WebAssembly**, reusing
the server module's typed table/row handles. The design is **Hybrid**: JavaScript
owns the WebSocket (opening, sending, receiving frames), while Haskell exposes four
synchronous wasm exports — `hs_subscribe`, `hs_on_frame`, `hs_send_message`,
`hs_set_name` — that JS calls directly. The reason for this split: GHC-wasm's reactor
model does not fire deferred Haskell closures installed as JavaScript callbacks (so
Haskell cannot own the socket and drive the event loop itself), but synchronous
JS→Haskell export calls work correctly. This was confirmed by a B2 spike before the
Hybrid design was adopted.

## Build

Inside the `.#wasm` nix dev shell:

```bash
bash scripts/build-web-hs.sh
```

Produces `dist/` (gitignored) containing:

- `chat-web.wasm` — the compiled Haskell client
- `ghc_wasm_jsffi.js` — the GHC wasm JS FFI shim (generated by `post-link.mjs`)
- `index.html`, `run.mjs` — the thin JS host page
- `vendor/browser_wasi_shim.mjs` — vendored WASI shim (CDN-free)

## Run in a browser

Serve `dist/` with any static file server, e.g.:

```bash
cd dist
python3 -m http.server 8080 --bind 0.0.0.0
```

Then open:

```
http://<host>:8080/?host=127.0.0.1:3000&db=quickstart-chat
```

Requires a running SpacetimeDB instance with the `quickstart-chat` module published.
See [`../README.md`](../README.md) and [`../server/`](../server/) for how to build and
publish the server module.

## Headless smoke test (no server required)

After building, run:

```bash
node node-smoke.mjs
```

This loads the wasm and exercises all four exports (`hs_subscribe`, `hs_on_frame`,
`hs_send_message`, `hs_set_name`) with synthetic BSATN frames. No server connection
needed. Expected output ends with `NODE SMOKE PASS`.

## Live round-trip check

With a published module and running SpacetimeDB server:

```bash
node live-smoke.mjs
```

This connects a real WebSocket, sends a message, and asserts that the message echoes
back rendered through `hs_on_frame`. Override defaults with environment variables:

```bash
HOST=127.0.0.1:3000 DB=quickstart-chat node live-smoke.mjs
```

This is exactly how the Hybrid client was verified against a live server.

## Publishing the server module (prerequisite)

```bash
nix develop .#wasm --command bash -c '
  bash ../server/scripts/build-wasm.sh
  spacetime publish --server local -b ../server/dist/chat-module.nowasi.wasm quickstart-chat -y
'
```

## Notes

- `web/vendor/browser_wasi_shim.mjs` is vendored from `@bjorn3/browser_wasi_shim@0.3.0`
  for CDN-free offline builds.
- `run.mjs` sets `#log.innerHTML` from the HTML string returned by Haskell's
  `hs_on_frame`. The `renderHtml` function in the Haskell source escapes `<`, `>`,
  and `&` in message content, but this is a quickstart demo and should not be pointed
  at an untrusted SpacetimeDB server.
- Form submits before the WebSocket is open are guarded: a "not connected yet" message
  is shown rather than throwing a silent error.
